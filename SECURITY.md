# Security Policy

This app is used for real by the university Tinkerer Laboratory and holds real student data, so we take security seriously.

## Reporting a vulnerability

**Please do not open a public GitHub issue for a security problem.** A public issue tells everyone about the weakness before it's fixed.

Instead, report it privately:

- Email the project maintainers directly. **Add a security contact email here before making the repository public.**
- Or use GitHub's private ["Report a vulnerability"](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) feature if it's enabled on this repo.

Include as much as you can: what the problem is, how to reproduce it, and what an attacker could do with it. We'll confirm we received your report, work on a fix, and credit you if you'd like.

## What counts as a security issue

Examples of things worth reporting privately rather than in a public issue:

- A way to view or download a **private** project or file without permission.
- A way to log in as, or act as, another user.
- A way to bypass the university-domain login restriction.
- A way to make the backend serve or accept file bytes it shouldn't (uploads/downloads are supposed to go straight to storage).
- Exposed secrets, credentials, or internal services.

## Please don't

- Don't run attacks against the live production site.
- Don't access, change, or delete data that isn't yours.
- Don't publicly disclose the issue until we've had a chance to fix it.

Thank you for helping keep the lab's data safe.
